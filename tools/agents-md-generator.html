    How agents read these files

    One AGENTS.md, every agent.

    AGENTS.md is plain Markdown with no required fields, described on agents.md as a README for coding agents. Codex, GitHub Copilot's coding agent, Cursor, Gemini CLI and many others read it. Claude Code reads CLAUDE.md first, which is why the generator adds a one-line CLAUDE.md that imports your AGENTS.md.

    This is the setup I use on this website's own repository: one AGENTS.md holds the commands, the standing rules and the deploy steps, and both Claude Code and Codex work from it. The rules that saved me most often are the specific ones, like "never push without asking" and the exact command to run before a deploy.

    Rules last checked on November 26, 2026 against the Claude Code memory docs, the Codex AGENTS.md docs and the GitHub Copilot docs. Agents change quickly, so check the docs for the version you use.

    What should an AGENTS.md include?

    The commands to install, run, build and test the project, the code style rules a linter cannot enforce, how to test a change, security rules such as where secrets live, and anything an agent must never do. Keep it to rules that matter on most tasks.

    AGENTS.md vs CLAUDE.md: do I need both?

    If your team uses Claude Code with any other agent, yes. Keep the shared rules in AGENTS.md and make CLAUDE.md a short file that starts with @AGENTS.md. Claude Code then loads the same rules, and you can add Claude-only notes below the import.

    Where do I put the files?

    In the repository root, next to your README. In a monorepo you can add more AGENTS.md files inside packages; most agents use the one closest to the code they are editing.

    How long should it be?

    Claude Code's docs suggest keeping each CLAUDE.md under 200 lines, and Codex stops reading instruction files after 32 KiB by default. Short and specific beats long and general.

    Does the tool store or upload my file?

    No. The generator and the checker run entirely in your browser. Nothing you type or paste is sent to a server.
